# Bank file signing (GAP-PAYROLL-DISBURSEMENT-03)

Bank payment files generated by payroll-service (`POST /v1/payroll/runs/:id/bank-file`) are
**signed by default**. Signing happens at file generation, is verified immediately
(self-check, fail closed) and the result is stored on the issuance record
(`payroll.disbursement_file_issuances`: `signature_format`, `signature`, `file_sha256`,
`signed_at`, `signing_key_fingerprint`, `encrypted_to_bank`). The file itself is not stored.

## Formats

| `format` | Applies to | Output |
|---|---|---|
| `pgp_detached` (default) | bank H2H / NEFT / RTGS / NACH files (csv, txt, fixed-width, zip) | ASCII-armoured OpenPGP detached signature `<file>.sig`, SHA-256, over the exact file bytes |
| `xml_dsig` | PFMS-style XML payment files | XML-DSig enveloped signature, RSA-SHA256, exclusive C14N (no sidecar). Payroll generates no PFMS XML today; pointing this at a non-XML file fails closed (`SIGNING_FORMAT_NOT_APPLICABLE`) |
| `pkcs7_detached` | banks that want CMS | DER `<file>.p7s` (stored base64), SHA-256 |
| `none` | dev / sandbox only | no signature; every response/UI says UNSIGNED. Refused (422 `UNSIGNED_NOT_ALLOWED_IN_PRODUCTION`) when `NODE_ENV=production` or the tenant integration environment is production |

Optional **encrypt-to-bank** (`encryptToBank`, default OFF): the signed file is OpenPGP-encrypted to the
bank's public key (`<file>.pgp`); the signature is over the unencrypted file bytes.

## Setting

`payroll.payroll_settings.bank_file_signing` (jsonb, NULL = default). API:
`GET/PUT /v1/payroll/bank-file-signing` (read: payroll_admin/payroll_officer/super_admin; write:
payroll_admin/super_admin, CQRS command -> consumer, before/after audit).

```json
{ "format": "pgp_detached", "perBankOverrides": { "SBIN": "pkcs7_detached" }, "encryptToBank": false, "keyRef": "default" }
```

`perBankOverrides` keys are the sponsor bank code (sponsor code / IFSC prefix). `keyRef` is an opaque
plain string resolved by a `SigningKeyProvider`; it never contains key material.

## Downloads

* `POST /v1/payroll/runs/:id/bank-file` returns the file and the headers `x-bank-file-signed`,
  `x-bank-file-signature-format`, `x-bank-file-sha256`, `x-bank-file-encrypted`, `x-bank-file-issuance-id`.
* `GET /v1/payroll/disbursement/files/:issuanceId/signature` returns the `.sig` / `.p7s`.
* `GET /v1/payroll/disbursement/files` lists issued files with their signing state.

`x-bank-file-sha256` (and the stored `file_sha256`) is the hash of the **plaintext** signed file. When
`encryptToBank` is on, the delivered `.pgp` has a different hash, and the bank needs the `.sig` / `.p7s` sidecar
(`GET .../files/:id/signature`) to verify the decrypted file.

Verify a PGP signature: `gpg --verify bank_transfer_X.csv.sig bank_transfer_X.csv` (import the public key
of the signing key first).

## Keys

* **Dev / sandbox** (`DevFileSigningKeyProvider`): one JSON key file, mode 600, default
  `~/.civitasone-payroll-signing-key` (override `PAYROLL_SIGNING_KEY_FILE`). It is generated on first use
  only if absent, or explicitly with `pnpm signing:init-dev-key` (run in the payroll-service package). It is never
  overwritten and never committed. It holds a dev OpenPGP RSA key and a dev RSA key + self-signed X.509
  certificate. Only `keyRef` `default` is served. For encrypt-to-bank in dev, put the bank's armoured public
  key at `$PAYROLL_BANK_PGP_KEYS_DIR/<BANKCODE>.asc`.
* **Production** (`KeystoreSigningKeyProvider`): stub that throws `NOT_IMPLEMENTED` until UAT. Because unsigned
  files are refused in production, bank-file generation fails closed (503 `SIGNING_NOT_IMPLEMENTED`) until a
  real keystore/HSM adapter is wired. The platform/tenant integrations (`bank_api` provider) can later carry
  the same `keyRef` string.
* `PAYROLL_INTEGRATION_ENVIRONMENT` (`production` | `sandbox` | `dev`) stands in for the tenant integration
  environment until the platform integrations land (`setIntegrationEnvironmentResolver` is the seam).

## Confirm per bank in UAT

Each sponsor bank's actual required signature/encryption format must be confirmed with the bank during UAT
and set through `perBankOverrides` (and `encryptToBank` plus the bank's public key).
