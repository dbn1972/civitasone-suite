## 4 · Cross-cutting architecture observations

**Strengths (across all 38 services):**
- **FORCE RLS universally present** in migrations: 35/38 services with domain logic have `FORCE ROW LEVEL SECURITY` + `CREATE POLICY tenant_isolation` on every tenant-scoped table. `gateway-service` and `queue-service` have no tenant tables (correct). `metadata-service` has 5 FORCE RLS statements but no application enforcement (STUB).
- **`app.tenant_id` GUC plumbing is correct** in all services examined: `shared/db.ts` wraps every `db.transaction()` with `SELECT set_config('app.tenant_id', $tenantId, true)` and `src/app.ts` sets the GUC in the request lifecycle via `resolveContext()`.
- **CQRS pattern** (route → zod → `queue.publish` → 202 → consumer → `markProcessed` → write → `outbox.enqueue` → cache invalidate) is consistently implemented across 35/38 services.
- **Transactional outbox + idempotent consumer** (`markProcessed(tx, messageId)` returning `false` to skip replays) is present in all consumer-bearing services.
- **PII at rest (DPDP Act)**: court-service (party PII — AES-256-GCM `encryptedText` type), visitor-service (pass data, Aadhaar face), grant-service (beneficiary Aadhaar DPDP §4 masking).
- **DLQ + retry**: court-service worker documents 3× exponential backoff (1s, 2s, 4s) then DLQ with full context. Pattern mirrored in other services.
- **correlationId** propagation: every log line, every envelope, every outbound event includes `correlationId`.

**Weaknesses / gaps:**
- `metadata-service`: 5 DB tables, safe expression rule engine, 1 migration — but **zero HTTP or event surface**. The service cannot be invoked.
- `notification-service`: `src/modules/email/smtp-sender.js` is missing — a production crash at startup on the email channel.
- `analytics-service`: BigInt type mismatch in `query-consumer` passes a decimal `"250.00"` to a `bigint` column — production data ingestion on any monetary fact will crash.
- All E2E test suites (37 in court-service, 16 in project-service, others) are `describe.skip` — no live-database proof exists for write paths in CI.
- `ml-service`: only 1 migration file for 13 modules — RLS policies are minimal (5 statements); the ML schema is the least-validated of all large services.
